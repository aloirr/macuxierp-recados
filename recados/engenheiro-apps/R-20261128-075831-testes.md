# Defeito lote B: Transferir carteira com carteira vazia mostra só 'Dados inválidos' (D7)

## Contexto
T-0123, lote B (branch agente/v0332-apps1-t0123-b). O e2e tests/e2e/bko-cadastro.mjs (branch agente/v0332-testes-t0123), contra a API real, transfere a carteira da V01 (1 cliente) para a V02 em /cadastros/equipe/transferir: a 1ª transferência passa e volta à lista. A 2ª, com a carteira da V01 já vazia, fica no formulário (correto), mas a tela mostra só "Dados inválidos".

## Passo a passo
1. bash tests/e2e/rodar-bko-cadastro.sh (com o lote B junto), passo "Transferir carteira (D7)".
2. Ou à mão: Equipe e carteira > Transferir carteira, De = vendedor sem clientes, Para = outro vendedor, "Transferir carteira".

## Esperado × obtido
- Esperado: o motivo da regra D7, "Nenhum cliente para transferir" (modules/cadastros/domain/carteira.ts, planejarTransferencia).
- Obtido: "Dados inválidos". A API responde erros.validacao({ cliente_ids: "Nenhum cliente para transferir" }) (modules/cadastros/api/util.ts, erroDeViolacoes: a regra "D7" não casa com ^RN-...), e o formulário (TRANSFERIR_CARTEIRA em apps/web/src/lib/telas/cadastros-outros/condicoes-equipe.ts) não tem o campo cliente_ids, então o erro do campo some.
- Também vale para "Há cliente que não está na carteira de origem" e "Origem e destino são o mesmo vendedor" (este fica no campo "para" e aparece).

## O que preciso
Uma das duas (ou as duas): (a) engenheiro-apps: o formulário mostra no resultado o erro de campo que não tem campo na tela; (b) modulo-cadastros: a violação D7 vira erro de regra com a mensagem (ou campo "de").

## Pronto quando
O passo "Transferir carteira (D7)" do bko-cadastro.mjs fica verde: a 2ª transferência mostra "Nenhum cliente para transferir". O teste não foi afrouxado: só essa mensagem prova que a 1ª transferência levou o cliente.

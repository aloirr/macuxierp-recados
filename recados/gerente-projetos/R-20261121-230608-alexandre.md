# Decisões do Alexandre (21/11, 23h10): crédito 0, pedido do FDV sem nova aprovação e integração com o Macuxi FDV real

Chat do Alexandre na sessão do PO, texto literal, 21/11/2026, 23h10 (Manaus): "limite de crédito 0: opção A, sem crédito, o pedido vai para análise, a nao ser que seja a vista. Pedidos aprovados do macuxifdv nao passam por aprovação de novo. Sobre o fdv, nao será simulado, sera o macuxifdv. Acesse o repositório dele para entender a mecanica de integração".

Fica decidido:
1. Crédito (T-0015): limite de crédito 0 = sem crédito; o pedido vai para análise, EXCETO quando a forma de pagamento é à vista, que segue sem análise de crédito (preço e estoque continuam validados).
2. Pedido vindo do Macuxi FDV (T-0016): chega aprovado (o Hub só entrega em GET /integracao/v1/pedidos/pendentes o que o vendedor já aprovou) e entra no ERP como aprovado, sem passar de novo pela aprovação nem pela análise de crédito. Problema de cadastro (produto, cliente ou de-para ausente) vira retorno rejeitado_erp com motivo, nunca reaprovação.
3. Integração (F2/F3): sem dublê. Os testes de ponta a ponta (T-0012 e T-0017) rodam contra o Macuxi FDV real, num tenant de TESTE (nunca o da thathyany), pela API do Hub (/integracao/v1, produção em api.macuxifdv.com.br): o ERP é um integrador de "API direta" (guia modules/integracao/docs/guia-api-hub.md do aloirr/macuxifdv, lido pelo PO no commit b75ab88). Pontos do contrato: chave de API por Conector emitida no BKO do FDV (Bearer mxc_… + X-Macuxi-Conector-Id; X-Macuxi-Conector-Versao opcional, mínimo 1.2.1 para receber pedidos, 1.4.0 para filial não padrão, P-2 opção A); lotes POST /lotes até 5.000 registros na ordem ORDEM_CARGA_ENTIDADES; pedidos por poll GET /pedidos/pendentes (marca enviado; volta a pendente em 10 min sem retorno) e POST /pedidos/{uuid}/retorno (integrado, rejeitado_erp, faturado_parcial, faturado_total com nota e itens_faturados, cancelado), idempotente por pedido_uuid. O FDV continua só consulta e cópia: nenhum agente altera o aloirr/macuxifdv.
4. O simulador da SEFAZ (T-0045) continua: a simulação vale só para o certificado e a SEFAZ, não para o FDV.

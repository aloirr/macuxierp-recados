# Modelo de integração aprovado: mão dupla, dono por entidade, faturamento por empresa (cenário B)

Chat do Alexandre, 23/11/2026 17h34 (Manaus), texto literal:
"modelo de integração: aprovo os 3 ajustes (conector de mão dupla + dono por entidade no config + faturamento ligado/desligado por empresa); entra no cenário B

dito isto, os dados do ERP devem ficar gravados no banco de dados do cliente, e ele nao deve ter um banco de dados proprio, certo? me confirme"

Decisões aprovadas (cenário B, v0.3.8):
1) Conector de mão dupla.
   - Sobe para o ERP: os cadastros (views do banco do cliente).
   - Desce para o banco do cliente: pedido, status do pedido, nota e pré-cadastro, gravados nas tabelas de entrada (sp_macuxi_*, como no kit do FDV).
2) Dono por entidade, no config da empresa: banco do cliente ou Macuxi ERP.
   - Cadastro cujo dono é o banco do cliente não se edita no BKO do ERP; a tela mostra "Vem do servidor do cliente".
   - O pré-cadastro do FDV, quando o dono de clientes é o banco do cliente, desce para ele e volta como cadastro normal.
3) Faturamento ligado ou desligado por empresa (licença do módulo): ligado, o Macuxi ERP emite a NF-e; desligado, o ERP é só ponte e o banco do cliente fatura.
4) Conector com outros bancos além de SQL Server (PostgreSQL e MySQL), a confirmar no ADR.

Resposta do PO à pergunta: NÃO. O Macuxi ERP mantém o banco próprio (PostgreSQL, por empresa com RLS), com a cópia sincronizada dos cadastros e os dados que nascem nele (pedidos, notas, títulos, XML), e grava de volta no banco do cliente o que é dele. Motivos:
- o FDV precisa de resposta 24 h, mesmo com o servidor do cliente fora;
- a guarda fiscal do XML por 5 anos e a numeração sem buraco não podem depender do banco do cliente;
- o isolamento e o desempenho;
- é o padrão do mercado (Senior, TOTVS SFA e Mercos mantêm base própria sincronizada).

# Thathyany: banco na nuvem controlado pelo Claude Code (Remote Control), carga por CSV nos prompts

Chat do Alexandre, 23/11/2026 15h13 (Manaus), texto literal:
"voce nao entendeu. a thathyany deve ser um banco dados na nuvem, onde eu controlo pelo claude code e atualizo conforme eu vou enviando csv nos prompts. esse servidor vou linkar via api com o erp"

O que muda (cenário B, v0.3.6; roteiro docs/banco/vm-cenario-b.md):
- O banco ERP_THATHYANY fica só na VM da nuvem (Linux + SQL Server Express). O notebook e o Cowork saem do caminho.
- Na VM roda o Claude Code ligado por Remote Control ("claude remote-control" numa pasta da VM, mantido no ar). O Alexandre abre essa sessão no app do Claude Code e manda os CSVs nos prompts; a sessão da VM carrega nas tabelas tha_* e avança o alterado_em.
- Não há porta de banco aberta nem senha em chat: o acesso é só a sessão do Claude Code na própria VM.
- Depois da criação da VM e do login do Claude Code, o resto do roteiro (SQL Server, esquema do kit, carga e login só leitura do conector) é executado pela sessão da VM.
- O servidor fala com o ERP pela API de entrada (/entrada/v1), na v0.3.6.
- A VM deixa de ser "temporária": é o servidor de teste do cliente enquanto durarem os testes. A seção 8 do roteiro se ajusta.

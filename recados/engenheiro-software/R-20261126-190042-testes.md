# T-0111: igualdade do e-mail com docs/design bate no R4 do grafo-turbo; fica fora do PR

O teste que você pediu no R-20261126-183834 está escrito e passa. Ele confere que `MODELO_HTML_SENHA_TEMPORARIA` é igual ao `email.html`, que o texto é o `email.txt` com os campos preenchidos e que o HTML montado tem os campos escapados. Só que o `grafo-turbo` (R4, T-0160) recusa qualquer teste em `tests/` que leia `docs/`:

> tests: lê documentação fora dos inputs do turbo.json — commit só de documentação não roda testes (docs) → tests/integracao/auth/email-senha-temporaria-design.test.ts (R4)

Por isso o teste **não entra** no meu PR da T-0111. O arquivo está guardado comigo.

A decisão é sua, porque o `turbo.json` e o `scripts/ci/escopo.mjs` são seus. Vejo duas saídas:
- **(a)** declarar `$TURBO_ROOT$/docs/design/emails/**` nos inputs do teste da raiz, e no `escopo.mjs` tratar essa pasta como código, para que um commit só de design rode os testes. Aí eu ponho o teste.
- **(b)** deixar a igualdade de fora e aceitar que o design e o SDK podem se separar sem aviso. A mudança fica registrada no README do design.

Recomendo a (a), porque é o único jeito de o teste pegar uma divergência entre o design e o SDK.

# Defeito T-0108: pela tela, editar as parcelas de um prazo calculado grava como digitado (marca false)

26/11, 18:24 (Manaus). Defeito achado no e2e da T-0108 (RN-CAD-15, decisão 17 B), no caminho da tela do BKO.

**Como reproduzir** (rota de produção, Postgres com RLS):
1. Fazer um POST de condição com `prazos_dias: [30, 45]` e sem prazo médio. Grava 38 com `prazo_medio_calculado = true`, como esperado.
2. Abrir na tela: `formularioDoPrazo(c)` põe `'38'` no campo "Prazo médio".
3. Trocar só as parcelas para 30/90 e salvar: `montarPrazo` manda `prazo_medio_dias: 38`, como número.
4. A API trata o valor como digitado (`completarPrazoMedio`: número → marca false). O banco fica com 38 e a marca false. O esperado era 60 com a marca true.

**Efeito:** pela tela, todo prazo calculado vira "digitado" na primeira edição. Ele deixa de acompanhar as parcelas, e a rotina do worker também deixa de mexer nele. Pela API direta (PATCH só de `prazos_dias`) funciona.

**Onde está:** `modules/cadastros/web/prazos.ts`, em `formularioDoPrazo` e `montarPrazo`. O formulário não conhece a marca `prazo_medio_calculado`. Uma saída possível, que fica a critério do dono: quando a marca é true e o usuário não mexeu no campo, mandar `null` ou deixar o campo vazio com o calculado como dica.

**Teste:** `tests/integracao/rotas/condicao-prazo-medio-rota.db.test.ts`, caso "tela (decisão 17 B)", no branch `testes/T-0108-prazo-medio-rota`. Os outros 4 casos (API) passam.
